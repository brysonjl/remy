# Existing application research

Research date: 2026-10-19. Target confirmed by the user: native macOS first, M4 Pro, macOS 27.0.1, primarily English, with browser tools and terminals/coding agents as important destinations. This is a source review, not a build, performance benchmark, security audit, or reliability certification.

## Recommendation

Use a **maintained personal fork of Dictate Anywhere as the first implementation candidate**, behind a baseline build/performance/reliability gate. It already implements most of the requested macOS experience, including Parakeet v2, custom cleanup, generic OpenAI-compatible endpoints, raw and transformed history, live preview, and clipboard-plus-paste. Rewriting those OS integrations first would discard substantial existing behavior and regression tests.

Keep Remy's product identity, data, signing, release feed, and configuration independent. Preserve upstream attribution and a record of imported commits. Add modular boundaries incrementally around session coordination, provider profiles, and durable history. A new Swift project becomes justified only if the baseline reveals problems that cannot be fixed economically, or if a separately specified product/platform requirement fundamentally conflicts with this foundation.

OpenWhispr is a valuable comparison and source of behavioral tests, especially if cross-platform support later becomes a requirement. For this Mac-first tool, its desktop/mobile, account/cloud-sync, meetings, connectors, and agent features add significant code and operational surface that Remy does not currently need.

## Dictate Anywhere: findings verified in code

**Native application and speech engine.** The project uses Swift/macOS frameworks. Its [dependency lock](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved) pins FluidAudio 0.17.5 (revision 0b1f46289fe27d95b5e66ad8be46e64f5ee02ae7), llama.swift 2.10549.0, and Sparkle 2.9.6. The [TranscriptionEngine protocol](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/TranscriptionEngine.swift#L276) already separates preparation, recording start, immediate capture stop, final decoding, cancellation, recovery-file transcription, and session vocabulary/context. This is a useful existing seam. The same file implements AVAudioEngine/AVCaptureSession capture, microphone startup handling, model-selection generation guards, batch models, and streaming variants. Parakeet selection maps the English v2 option to FluidAudio v2.

**Hotkeys.** [HotkeyService](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/HotkeyService.swift) uses a CGEvent tap for key-down, key-up, and modifier changes, with cached bindings, cancellation gestures, and retry on failed tap creation. The app distinguishes held recording from toggle recording. Its native path is much closer to Remy's needs than implementing shortcut handling from scratch.

**Finalization and cleanup.** [AppState.finishDictation](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/AppState.swift#L1779) stops microphone capture, finalizes recognition, optionally removes fillers, then dispatches to Apple Intelligence, S1-mini, Ollama, OpenRouter, or generic OpenAI-compatible cleanup. Exceptions preserve the pre-cleanup text. Cancellation is checked before delivery; the code commits delivery once and saves history before relinquishing recovery audio.

The [OpenAI-compatible service](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/OpenAICompatiblePostProcessingService.swift) already accepts a base URL, arbitrary model ID, API key, custom prompt, vocabulary, and optional context. It supports model discovery, credential-scoped caches, structured-output capability fallback, a 5-second discovery timeout, and a 60-second completion-request timeout. The shown implementation awaits a complete HTTP response; it is not incremental token output. A generic adapter therefore exists, but named provider profiles, reliable per-session configuration snapshots, tighter latency budgets, and explicitly surfaced failure states remain Remy work. A 60-second network timeout is too loose to equate with a low-latency dictation SLA.

**History gap.** The [entry type](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/Settings.swift#L873) stores ID, transformed text, date, and optional raw text. [History insertion caps it at 50 entries](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/Settings.swift#L2121). [Persistence](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/TranscriptHistoryPersistence.swift) serializes an entire JSON array into UserDefaults on a serial queue. A flush joins queued writes; this is not a database transaction or explicit filesystem durability guarantee. Remy should migrate to a dedicated SQLite repository with raw ASR, replacement result, cleanup attempts, actual delivered text, model/prompt versions, timing, errors, and delivery outcomes. Preserve original entry IDs and timestamp/raw-text semantics during migration; do not invent missing raw transcripts.

**Insertion.** [TextInserter](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/TextInserter.swift#L655) copies first, validates the destination process/frontmost application, and returns copied-only when automatic delivery is unsafe or unavailable. Its paths include Accessibility paste, AppleScript, and CGEvent fallback. It avoids blind retries after a possibly dispatched paste and rechecks destination readiness around awaits. The app also has special handling for lists, keyboard layouts, cursor spacing, and secure/excluded context. Preserve this behavior while simplifying product scope; do not replace it with a single unguarded Cmd+V.

The final insertion text can differ from the cleaned history text because insertion formatting is applied afterward. Remy must explicitly record the delivered text and outcome. Process identity alone is also insufficient to prove the same document or focused field remained selected; test and strengthen field-level destination policy.

**Safety checks are limited.** [TranscriptCleanupIntegrity](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/TranscriptCleanupIntegrity.swift) checks numeric-literal preservation for relevant transformations; it explicitly does not claim semantic verification. [Cleanup planning](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/TranscriptCleanupPlan.swift) preserves paragraph separators and guards incomplete/context-overflow output. Neither proves that a cleanup model preserved negation, names, intent, or corrections. Those require a task-specific evaluation set.

**Credentials and updates.** Settings uses Keychain for OpenRouter, OpenAI-compatible, and AssemblyAI secrets. [SoftwareUpdater](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/e420448de6e2099d33e050a4b419722032fd7519/Dictate%20Anywhere/SoftwareUpdater.swift) starts Sparkle automatically in non-Debug builds. A Remy fork must disable the inherited updater or replace the feed and signing trust before running a branded release build. Separate bundle IDs, Keychain services, Application Support paths, login items, and development/release identities before daily use.

**Maintainability and tests.** AppState and TranscriptionEngine are approximately 133 KB and 109 KB respectively at this revision; Settings is another large coordination surface. This is substantial integration code, not a small library. Avoid a broad reorganization concurrent with feature work. The tree contains 71 XCTest files named *Tests.swift, including startup/teardown, permission lifecycle, cancellation, insertion, privacy, concurrency, history ordering, and pipeline benchmarks. Reviewed examples exercise raw/final history persistence and deletion ordering, cleanup contracts, cancellation, and paste finalization. These are useful assets, but file counts are not execution results or coverage percentages. The inspected release workflow creates a draft release; it does not build or run these tests. A fresh Remy CI setup and macOS runtime test pass are required.

## OpenWhispr: findings verified in code

**Architecture and speech.** [package.json](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/package.json) identifies an Electron/React desktop application with native helper builds and a Node test suite. [Parakeet management](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/src/helpers/parakeet.js) handles model downloads, validation, warmup, and the sherpa-onnx execution path. [WebSocket server management](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/src/helpers/parakeetWsServer.js) distinguishes offline and online model runtimes, manages process identity and health, and bounds completion waits. A WebSocket transport does not itself imply that a batch Parakeet checkpoint becomes a true streaming model.

**Hotkeys and paste.** [HotkeyManager](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/src/helpers/hotkeyManager.js) combines Electron globalShortcut with platform-native listeners; it rejects unsupported Fn combinations and checks whether a hotkey can supply key-release events for push-to-talk. [Clipboard management](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/src/helpers/clipboard.js) serializes paste operations, handles clipboard restoration, and falls back among platform helpers. The [macOS helper](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/resources/macos-fast-paste.swift) resolves shortcuts against the active keyboard layout instead of assuming a US key code. OpenWhispr normally restores the original clipboard unless disabled; Remy's requested copy-and-paste behavior should retain the dictated text by default.

**History and recovery.** [database.js](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/src/helpers/database.js#L331) stores transcription text/raw_text, audio metadata, provider/model, status/errors, route kind, and cloud-sync fields in SQLite. The broader database implementation is approximately 316 KB and includes many unrelated features; reuse schema ideas rather than importing it wholesale. [Recording spool](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/src/helpers/recordingSpool.js) writes recording chunks to renderer IndexedDB so a stalled main process does not necessarily lose the recording. This illustrates why recovery must not depend exclusively on the component most likely to hang.

**Provider/cleanup behavior.** [OpenAI provider code](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/src/services/ai/inferenceProviders/openai.ts) supports configured endpoints, API-key scoping, request cancellation, and endpoint/parameter compatibility fallback. [AudioManager](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/src/helpers/audioManager.js) combines recording, streaming finalization, cleanup, translation, agent routing, and failure recovery. Its approximately 247 KB size reinforces the cost of inheriting the whole product.

**Tests and transfer lessons.** The tree has 819 desktop test files matching test/**/*.test.js; only selected cases were read, and none were executed. [Cleanup fallback tests](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/test/helpers/audioManagerCleanupFallback.test.js) verify raw text remains available with attached cleanup failure details. [Clipboard restoration tests](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/test/helpers/clipboardRestore.test.js) and [streaming finalization tests](https://github.com/OpenWhispr/openwhispr/blob/bcd5ba61d05455761011964e5f4764cb5aa303a7/test/helpers/audioManagerStreamingFinalization.test.js) provide valuable scenario inventories. Port relevant behavior into native tests; do not mistake mocked tests for proof that actual apps accept paste or that audio devices recover correctly.

## Fork decision and execution gate

1. Obtain the complete pinned Dictate Anywhere checkout and run it under an isolated development identity, with inherited update channels disabled and cloud speech/context sharing off.
2. Build and run the existing tests on the actual target Mac. Measure warm/cold start, first preview, stop-to-raw, cleanup, stop-to-paste, memory, and model-load failures with the user's microphone and common destination apps.
3. Validate the exact Spokenly Parakeet v2 experience against the chosen FluidAudio artifact. Do not promise the same 496 MB packaging or accuracy merely from the model-family name.
4. Verify the supplied Ollama cloud base URL/model through the generic compatible adapter, plus a local Ollama model. Preserve exact model IDs; do not hard-code a commercial provider catalog.
5. If baseline results pass, deliver small increments: identity/update isolation; durable history; immutable provider/prompt session snapshots and configurable profiles; bounded cleanup/fallback behavior; field-aware insertion; performance/recovery instrumentation.
6. Extract a session coordinator and typed event seam only as needed to support those increments. Keep wake-word activation as a future input source, vocabulary replacement as an explicit pipeline stage, and computer actions as a separate opt-in consumer of finalized intent.
7. If baseline fails, record concrete failures and a bounded repair estimate before choosing a new native implementation. Electron or greenfield Swift is not inherently more reliable than the existing native code.

## Claims not established by this review

No benchmark here establishes either application's latency, crash rate, battery use, model quality, or daily reliability. README claims such as local processing, release notarization, live-preview cadence, and optional cloud behavior are useful orientation, not substitutes for runtime verification. In particular, privacy must be described per selected route: optional cloud ASR sends audio; remote cleanup sends text; context sharing is another decision. Do not repeat a blanket “audio never leaves the Mac” claim for a build that enables cloud speech.

This review supports a fork-first engineering decision and identifies concrete gaps. It does not assert that either upstream app is already a fully verified replacement for Spokenly.
