# Remy diagnostics policy

Default application diagnostics describe operations and bounded results. They must not record audio, transcript or selected-field text, prompts, provider response/error bodies, API keys or credential hashes, file paths, document/window titles, target process identifiers, microphone unique identifiers, or arbitrary error descriptions. Marking sensitive content `.private` is insufficient: a diagnostic capture can reveal private interpolations.

`RemyDiagnostics.subsystem` uses the active bundle identity, with `io.github.brysonjl.remy` as its fallback; development and release remain distinguishable. `RemyDiagnostics.errorCategory(_:)` emits only `cancelled`, `timeout`, `transport`, or `other`. It does not interpolate the error, its type, domain, user info, URL, or localized description. Do not add arbitrary provider text to a new error category. The original error can remain in the service's control flow for schema adaptation and user-facing recovery; logging must classify it separately.

Performance traces may contain a session UUID, known engine/mode/state labels, counts, durations, numeric system status, OS/hardware model, and explicitly scoped numeric window-presentation geometry. Never use a free-form model name, endpoint, input-source name, or `.error(String)` associated payload as a trace label. Existing trace APIs accept strings; this policy is a call-site contract, not automatic string redaction. Add only narrowly justified metadata and test its producers.

Structured native audio-format diagnostics use numeric rates/counts rather than arbitrary descriptions. Hotkey and insertion logs describe state/formatting decisions without recording keys pressed or delivered text. Provider requests must not log their bodies, authorization headers, HTTP error bodies, or raw provider messages, even on failure. AssemblyAI's retained code uses a static fallback warning and is gated off in the supported Remy build.

The app configures FluidAudio logging at startup; normal runs suppress SDK debug mirroring. Explicit SDK debug mode is for local investigation only and requires separate inspection before sharing logs. This policy does not claim all third-party/native runtime stderr is automatically filtered. Review actual captured output before sharing it, and do not upload raw logs or attach them to CI artifacts by default. CI validation artifacts must use the repository's explicit allowlist and secret checks.

Transcript history and deliberate exports are product data, not diagnostics. The opt-in baseline harnesses may write public synthetic input/output artifacts; their scope and local ignored destinations are documented separately. Personal recordings, keys, preferences domains, and Keychain contents are never diagnostic fixtures. Diagnostic tests use synthetic sentinels and isolated state.

Settings schema version 1 introduces only a marker in Remy's defaults domain. It does not implement settings export, provider-profile migration, SQLite history, or a durable multi-key transaction. Unsupported/malformed schemas must stop before settings initialization can write preferences or initialize services.
